# RentPro — โกดังให้เช่า 4 หลัง

เว็บใช้งานจริง: https://omrjco.github.io/rentpro/
ตัวอย่างแยกจากข้อมูลจริง: https://omrjco.github.io/rentpro/demo.html#properties

## ใช้งานครั้งแรกและหลายอุปกรณ์

เปิดจากเครื่องที่มีข้อมูลเดิมก่อน สร้างบัญชีอีเมล/รหัสผ่าน ยืนยันอีเมลและเข้าสู่ระบบ ระบบให้เลือกนำข้อมูลในเครื่องเข้าบัญชีพร้อมเก็บสำเนา หรือใช้ข้อมูลออนไลน์เดิม การเลือกใช้บัญชีอื่นไม่รวมข้อมูลข้ามบัญชีโดยอัตโนมัติ จากนั้นอุปกรณ์อื่นเข้าสู่ระบบด้วยบัญชีเดิม

บันทึกใน IndexedDB ก่อนและซิงค์ออนไลน์อัตโนมัติ ร่างบิลและภาพแนบรวมอยู่ในการซิงค์ มีสถานะรอซิงค์/สำเร็จ/ผิดพลาด ข้อมูลที่ยังซิงค์ไม่สำเร็จไม่ถูกลบ ออกจากระบบหลังซิงค์ข้อมูลครบ ตรวจการเปลี่ยนแปลงทุก 15 วินาทีเมื่อไม่ได้แก้ฟอร์มหรือร่างบิล ปิดหน้าฟอร์ม/เปลี่ยนหน้าเพื่อโหลดข้อมูลใหม่

## ฟังก์ชันที่ใช้งาน

- ภาพรวม: ค่าเช่า ยอดรับและยอดค้างตามรอบ
- ทำบิล: บิลหลักน้ำ–ไฟ มิเตอร์ย่อย ตรวจและออกใบแจ้งหนี้ เก็บต้นทุนและภาพบิลแต่ละเดือน ไม่มีทะเบียนรายจ่ายเพิ่มเติม
- รับชำระ: เต็ม/บางส่วน ใบเสร็จ หลักฐาน และการยกเลิกพร้อมเหตุผล
- ห้องและผู้เช่า: ข้อมูลครบตั้งแต่เพิ่มผู้เช่าและสัญญา เลขสัญญา WH-ปีพ.ศ.-ลำดับ4หลัก อายุ 1–3 ปี คำนวณวันสิ้นสุดก่อนวันครบรอบ
- สัญญาฉบับเต็ม: 17 ข้อจากไฟล์ผู้ใช้ ตรวจช่องว่าง แบ่ง A4 พร้อมแนบท้ายมิเตอร์/สูตรค่าน้ำ–ไฟ เก็บ snapshot ณ วันออกและฉบับก่อนหน้าใน audit
- ตั้งค่า: ผู้ให้เช่า บัญชีออนไลน์ สำรอง JSON และประวัติรายการ

ภาพรองรับ PNG/JPEG/WebP ไม่เกิน 5 MB ต่อภาพ ข้อมูลตัวอย่าง 4 หลัง/8 บิลแยกจากข้อมูลจริงอย่างเด็ดขาด หน้ารุ่นเดิม original.html ส่งต่อมายังระบบปัจจุบันแล้ว ไม่มีการใช้งาน Google Sheets, LINE/Telegram Notify หรือฟอร์มตั้งค่า Firebase เดิม

## ต้นทุนค่าน้ำ–ไฟ

ต้นทุนรอบปัจจุบัน = ค่าการใช้ + ค่าบริการ + Ft + VAT ตามบิล − ส่วนลด ไม่รวมค้างเก่า ค่าปรับ และเงินประกัน หารด้วยหน่วยบิลหลัก คิดผู้เช่าตามหน่วยมิเตอร์ย่อย ส่วนต่าง ห้องว่างและเศษปัดทศนิยมเป็นต้นทุนเจ้าของ ไม่มีบวกเพิ่ม บิลที่ออกแล้วเก็บยอด สูตรและข้อมูล ณ วันออก ไม่เปลี่ยนตามสัญญาหรืออัตราในรอบใหม่

## แหล่งข้อมูลและความเป็นส่วนตัว

`online-cloud.js` ใช้ Supabase Auth ผ่าน supabase-js 2.49.1 ที่ระบุเวอร์ชันตายตัว ไม่มี secret/service-role key ใน frontend ตาราง rentpro_state และ rentpro_records แยก owner_id ด้วย RLS เทียบ auth.uid() RPC เป็น SECURITY INVOKER พร้อม search_path คงที่ จำกัดให้ authenticated และปฏิเสธ anon ไม่มีการเปลี่ยน schema หรือสิทธิ์ของแอปอื่น

`rentpro-cloud-schema.sql` คือ schema ที่เผยแพร่ผ่าน migration rentpro_private_cloud_sync เก็บข้อมูลเป็นราย entity/ภาพแบบ chunk และใช้ revision เปรียบเทียบในธุรกรรมเพื่อไม่ให้เครื่องหนึ่งทับอีกเครื่อง รวมข้อมูลแบบสามทางและตรวจการรับชำระซ้ำ/สัญญาหรือบิลซ้ำก่อนส่ง เมื่อข้อมูลเดียวกันแก้ขัดกันจะหยุดพร้อมรักษาข้อมูลเครื่องไว้ ในตั้งค่าบัญชีจะมีปุ่มใช้ข้อมูลออนไลน์ล่าสุด ซึ่งเก็บสำเนาแยกบัญชีและดาวน์โหลดไฟล์ก่อนใช้ข้อมูลคลาวด์แทน

ข้อมูลจริงไม่อยู่ใน repository หรือ GitHub Pages บัญชีแต่ละคนเข้าถึงได้เฉพาะข้อมูลของตน ข้อมูล/ฐานเปรียบเทียบ/ร่างบิลในเครื่องแยกบัญชี สำรองข้อมูลเครื่องก่อนย้ายออนไลน์ และไม่นำการตั้งค่าเก่า/โทเคนแจ้งเตือนขึ้นคลาวด์

## พัฒนาและตรวจ

ใช้ Python 3 และ Node.js 20+

```
python3 build-v4.py
npm test
```

แก้ไฟล์ source แล้ว build เป็น index.html และ demo.html สำหรับ GitHub Pages ส่วน dist ใช้ตรวจภายใน ห้าม commit ข้อมูลผู้เช่าจริง ไฟล์สำรอง หรือ credentials ส่วนตัว

ชุดตรวจครอบคลุมต้นทุนและการปัดเศษ บิล MEA/ประปาตัวอย่าง รับชำระบางส่วน การยกเลิก/คืนยอด ความขัดแย้งหลายเครื่อง ขนาดภาพ 5 MB แยกตัวอย่าง/ข้อมูลจริง สัญญาครบ 17 ข้อและอายุ 1–3 ปี ทดสอบ SQL RLS ด้วยบัญชีจำลองสองรายใน transaction แล้ว rollback รวมถึง anonymous REST ถูกปฏิเสธ ตรวจ schema ด้วย security advisor แล้วไม่พบรายการที่เกี่ยวกับ RentPro

การสร้าง/ยืนยันบัญชีอีเมลและการย้ายข้อมูลจริงต้องทำโดยเจ้าของบนเครื่องที่มีข้อมูล ทดสอบหน้าล็อกอินและตัวอย่างผ่าน browser โดยไม่สร้างบัญชีหรือส่งอีเมลแทนผู้ใช้
